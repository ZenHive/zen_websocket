## Findings and fixes

1. The Descripex surface marked the caller-created request maps for
   `RateLimiter.deribit_cost/1`, `binance_cost/1`, and `simple_cost/1` as
   `:exchange_data`. Descripex 0.13.0 defines caller-supplied parameters as
   `:value`; the annotations and surface tests now reflect that contract.
2. The changelog omitted task 18 from Unreleased and task 15 from 0.7.0, and it
   still claimed that CI invoked `mix ci` after the workflows were removed. The
   release record now describes the shipped validator/API-surface changes and
   the repository's manual gate accurately.
3. README, CONTRIBUTING, USAGE_RULES, Architecture, and the usage validator
   contradicted the repository's actual test policy. They now distinguish pure
   unit tests, the local real Cowboy/WebSock stack, and opt-in live-provider
   tests. The validator no longer mistakes `MockWebSockServer` or
   `:mock_server_unavailable` for dependency stubs, and a whole-library scan
   regression test requires zero diagnostics.
4. Supervision guidance overstated handler requirements, described every client
   as having its own supervisor, conflated transport backoff with supervisor
   restarts, and contained a `Logger.warn/1` callback for a message the example
   process would not receive. The guidance now matches the DynamicSupervisor and
   Client behavior, and the dead callback was removed.
5. `echo.websocket.org` no longer supplies the echo contract assumed by the
   shipped subscription example and external tests: a live probe returned a
   service banner instead of the sent payload. Deribit testnet and its official
   `public/subscribe` documentation confirmed a public `100ms` subscription and
   the authorization error for a `raw` channel. This needs a coordinated example
   and live-test rewrite, so it is tracked as roadmap task 20 rather than hidden
   behind permissive assertions.
