## Findings and fixes

1. The contract's fallback resolver matched any missing qualified module by its
   final segment. `MyApp.Config.not_a_real_function/0` was therefore checked as
   `ZenWebsocket.Config.not_a_real_function/0`, contradicting the documented
   rule that application-supplied modules are ignored. Fallback resolution is
   now limited to unqualified module names, with regressions for both the
   ignored qualified name and the retained short-name lookup.
2. The production supervision example installed
   `fn message -> send(self(), ...) end`. Because `self/0` ran when the Client
   invoked the callback, frames were sent back to the Client rather than to the
   example GenServer. The example now captures the owner during `init/1` and
   handles the forwarded message.
3. `UsagePatterns.supervised_client_spec/0` documented a frame handler but its
   returned child specification still omitted one, so the executable example
   disagreed with its new `@doc` and discarded unsolicited frames. The returned
   options now include a callable logging handler, covered by a focused unit
   test.

The range contains no leftover debug output, dead code, inconsistent naming, or
additional CHANGELOG gap. The existing Unreleased entry already records the
supervised-handler requirement; the remaining landed changes are test and
documentation infrastructure. No discovery task was filed because every
finding was fixed inline. No reviewer rejections were recorded for this range.
